# X25519, Ed25519 keys and hybrid encryption

[← Guide index](../README.md) · Crate: [x25519](../crates/x25519.md) · Built on: [SHA-512, HMAC, HKDF](sha-hmac-hkdf.md), [AES](aes.md) · Security: [defense.md § X25519](../../defense.md#x25519)

## The idea

X25519 (RFC 7748, Bernstein 2006) is **Diffie-Hellman key exchange on an elliptic curve**,
Curve25519. Each party has a 32-byte private scalar `a` and a 32-byte public key `A = a·G`
(the base point `G` "added to itself" `a` times). Two parties derive the same shared secret
`a·B = b·A` without ever sending it. Recovering `a` from `A` (the elliptic-curve discrete
logarithm) costs about `2^126` operations: 128-bit security with 32-byte keys, where RSA
needs 3072-bit keys.

`my_pgp X25519` turns this key exchange into **encryption**: the sender makes a throw-away
(ephemeral) key pair, derives a shared secret with the recipient's public key, and uses it to
key AES and HMAC. The recipient redoes the exchange with their private key.

Read first: [math primer § 5–6](../math-primer.md#5-finite-fields) (finite fields, groups,
Diffie-Hellman).

## Theory

### The field GF(2^255 − 19)

Coordinates are integers modulo the prime `p = 2^255 − 19`. This prime is chosen for speed:
since `2^255 = p + 19`, we have

```
2^255 ≡ 19 (mod p)
```

So when a product overflows past bit 255, the overflowing part `h·2^255` can be replaced by
`h·19`: reduction is a multiplication by 19 and an addition, never a division.

### The curve and the Montgomery ladder

Curve25519 is the Montgomery curve `y² = x³ + 486662·x² + x` over GF(p). X25519 only uses the
`x` coordinate, called `u`. The base point has `u = 9`.

To compute `k·P` the **Montgomery ladder** keeps two points `R0`, `R1` whose difference is
always `P`. For each bit of `k` from the top:

```
if bit = 0:  R1 = R0 + R1,  R0 = 2·R0
if bit = 1:  R0 = R0 + R1,  R1 = 2·R1
```

Because `R1 − R0 = P` is known, "differential addition" can add the points using only their
`u` coordinates. Both branches do exactly **one addition and one doubling**; they differ only by
which point is which, so the code swaps the points (in constant time) instead of branching.

Points are kept in **projective coordinates** `(X : Z)` with `u = X/Z`: the formulas then need
no division, and a single inversion at the very end gives `u = X·Z⁻¹`.

### Clamping

Before use, the scalar is "clamped":

- the 3 low bits are cleared: the scalar becomes a multiple of 8, the curve's **cofactor**, so
  any small-order component of a malicious point is wiped out;
- bit 255 is cleared and bit 254 set: every scalar has the same top bit, so the ladder always
  runs the same 255 steps (constant time) and never meets a zero scalar.

### Ed25519 keys

The subject's example keys are an **Ed25519** pair (RFC 8032), the signature scheme on the
twisted Edwards curve `−x² + y² = 1 + d·x²·y²` with `d = −121665/121666`. It is the **same
group** as Curve25519 in other coordinates. So `my_pgp` converts, like libsodium does:

- **Private**: the key is a random 32-byte seed; its scalar is the first 32 bytes of
  `SHA-512(seed)` (then clamped as above).
- **Public**: the point `scalar·B` on the Edwards curve, encoded as its `y` (255 bits) with the
  sign (parity) of `x` in the top bit. Its X25519 form is `u = (1 + y) / (1 − y)`.

Both routes agree: `X25519(scalar, 9)` equals the `u` of the converted Edwards public key.

### Hybrid encryption (ECIES-like)

`./my_pgp X25519 -c <public>`:

1. Draw a random ephemeral scalar `e`, a 16-byte nonce; `E = X25519(e, 9)`.
2. `s = X25519(e, recipient u)`. Reject an all-zero `s` (a low-order public key gives it).
3. **HKDF-SHA256** with salt `E` and info `"my_pgp X25519 AES-256-CTR"`: two 32-byte keys,
   `k_enc` and `k_mac`.
4. **AES-256-CTR**: cipher `nonce, nonce+1, nonce+2, …` with `k_enc` and XOR the results with
   the message. No padding: any binary message comes back exactly.
5. `tag = HMAC-SHA256(k_mac, E || nonce || ciphertext)`.
6. Output hex `E || nonce || ciphertext || tag`.

`-d <seed>` splits the input, recomputes `s = X25519(scalar, E)` and the keys, **checks the tag
in constant time first**, and only then deciphers. A wrong key or any modified byte exits 84.
This is **encrypt-then-MAC**, the safe order.

### Field elements

```rust
pub struct FieldElement { limbs: [u64; 5] }      // 5 × 51 bits = 255 bits
```

A value is `l0 + l1·2^51 + l2·2^102 + l3·2^153 + l4·2^204`. Limbs have 13 spare bits in their
`u64`, so additions can be chained without carrying immediately.

**Multiplication** is schoolbook on 5 limbs (25 products in `u128`). A product `a_i·b_j` lands
at weight `2^(51(i+j))`; when `i + j ≥ 5` that is `2^255 · 2^(51(i+j−5)) ≡ 19 · 2^(51(i+j−5))`,
so it is folded back into limb `i+j−5` with a factor 19:

```rust
a[0]*b[0] + 19 * (a[1]*b[4] + a[2]*b[3] + a[3]*b[2] + a[4]*b[1]),   // limb 0
a[0]*b[1] + a[1]*b[0] + 19 * (a[2]*b[4] + a[3]*b[3] + a[4]*b[2]),   // limb 1
…
```

`from_wide` then propagates carries: each limb keeps 51 bits and passes the rest up; the carry
out of limb 4 re-enters limb 0 multiplied by 19. Two passes bring every limb back to ~51 bits.

**Subtraction** computes `a + 2p − b` so limbs never go negative.

**Inversion** is Fermat: `x⁻¹ = x^(p−2)`. `p − 2 = 2^255 − 21` is a fixed, public 255-bit
number whose bits are all ones except bits 2 and 4, so `invert` is square-and-multiply that
multiplies when `bit >= 5 || bit ∈ {0, 1, 3}`: the same steps for every input.

**`to_bytes`** first reduces to the unique representative below `p` (`canonical`) with a
masked subtraction, since the value may be a secret shared key.

### The ladder

```rust
for position in (0..255).rev() {
    let bit = (scalar[position / 8] >> (position & 7)) & 1;
    swap ^= bit;                                          // swap only when the bit changes
    FieldElement::conditional_swap(&mut x2, &mut x3, swap);
    FieldElement::conditional_swap(&mut z2, &mut z3, swap);
    swap = bit;

    let a = x2 + z2;  let aa = a.square();
    let b = x2 - z2;  let bb = b.square();
    let e = aa - bb;
    let c = x3 + z3;  let d = x3 - z3;
    let da = d * a;   let cb = c * b;
    x3 = (da + cb).square();                              // differential addition
    z3 = x1 * (da - cb).square();
    x2 = aa * bb;                                         // doubling
    z2 = e * (aa + e * A24);                              // A24 = (486662 − 2) / 4 = 121665
}
```

These are the RFC 7748 formulas. `conditional_swap` exchanges two elements under a mask
(`mask & (left ^ right)` XORed into both), so no branch depends on the scalar.

### Ed25519 ([ed25519.rs](../../../crates/x25519/src/ed25519.rs))

- `scalar(seed)`: `SHA-512(seed)[..32]`.
- `public_key(seed)`: clamp, then `base().multiply(&scalar)` on the Edwards curve, then
  `encode()`.
- Curve constants are **computed**, not hard-coded: `d = −121665 · 121666⁻¹`; the base point
  has `y = 4/5`, and `x` is recovered with a square root (`sqrt`, using `p ≡ 5 mod 8`:
  `x = v^((p+3)/8)`, times `√−1` if needed) and the even sign chosen.
- Points use **extended coordinates** `(X, Y, Z, T)` with `x = X/Z`, `y = Y/Z`, `T = X·Y/Z`.
- `add` is the "add-2008-hwcd-3" formula for `a = −1`: 9 field multiplications, no inversion,
  and **complete**: it is correct for doubling and for the identity too, so one formula does
  everything.
- `multiply` is **double-and-add-always**: at each of 256 bits, compute `2R` and `2R + P`, keep
  one with a constant-time swap.
- `to_montgomery(public)`: `(1 + y) · (1 − y)⁻¹`.

### Hybrid encryption ([lib.rs](../../../crates/x25519/src/lib.rs))

- `cipher` and `decipher` follow the six steps above.
- `derive_keys` is HKDF written out:
  `prk = HMAC(E, s)`, `k_enc = HMAC(prk, info || 1)`, `k_mac = HMAC(prk, k_enc || info || 2)`.
- `aes_ctr` ciphers the counter with `Aes::cipher_block` and XORs; `increment_counter` adds 1
  to the counter as a big-endian number.
- `constant_time_eq` ORs all byte differences before comparing to 0.
- `validate_shared_secret` rejects an all-zero secret without early exit.

## Optimisations

| Technique | Why it is faster |
|---|---|
| Prime `2^255 − 19` | Reduction is "multiply the overflow by 19", no division. |
| 51-bit limbs in 64-bit words | Products of two limbs fit in `u128` with room to sum five of them (×19); carries can be delayed. |
| Projective `(X : Z)` ladder | No inversion per step (an inversion costs ~250 multiplications); one at the end. |
| Ladder step | 4 squarings + 6 multiplications per bit, independent of the bit. |
| Deferred swap (`swap ^= bit`) | Swaps only when consecutive bits differ; a final swap fixes the last state. |
| Extended Edwards coordinates | Addition in 9 multiplications, no inversion, no special cases. |
| Hybrid design | Curve operations twice per message; the data goes through AES-CTR. |

Possible improvements, not done: `invert` uses plain square-and-multiply (255 squarings, 253
multiplications) where the reference code uses an addition chain (254 squarings, 11
multiplications); the Edwards base-point multiplication could use precomputed tables.

## Constant time

- The ladder runs exactly 255 steps and swaps with masks.
- `invert` and `pow` branch only on public exponents.
- `canonical` uses a masked final subtraction.
- Ed25519 `multiply` always does both the doubling and the addition.
- The HMAC tag and the zero-secret check scan every byte.

`cargo run --release --bin timing` checks `x25519-scalar` ([constant-time-audit.md](../../constant-time-audit.md)).
