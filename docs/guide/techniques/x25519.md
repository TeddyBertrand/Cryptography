# X25519, Ed25519 keys and hybrid encryption

[← Guide index](../README.md) · Math and code: [deep dive](../deep-dive/x25519.md) · Crate: [x25519](../crates/x25519.md) · Security: [defense.md § X25519](../../defense.md#x25519)

## In one sentence

Two people each mix their secret with the other's public key and land on the same shared
secret, without ever sending it; Bernstein's Curve25519 makes this fast, safe and tiny
(32-byte keys).

## The picture

The classic analogy is paint mixing:

1. Everyone agrees on a common colour (the curve's **base point**).
2. Alice mixes in her secret colour and publishes the result. Bob does the same.
3. Each adds their own secret to the other's published mix. Both end with the **same final
   colour**.
4. An eavesdropper sees both published mixes but can't "unmix" them to find the secrets.

On an elliptic curve, "mixing" is multiplying a point by a secret number. Going forward is
fast; going back (finding the number) is hopeless: about `2^126` operations. That's the same
strength as a 3072-bit RSA key, with 32-byte keys.

**Why Curve25519?** Daniel J. Bernstein designed it (2006) to be hard to implement wrong:
the prime `2^255 − 19` makes the math fast, every secret takes exactly the same steps (no
timing leaks), and malicious public keys are neutralised by design.

## Turning a key exchange into encryption

Key exchange gives a shared secret, not encryption. my_pgp bridges it (like ECIES):

1. Make a throw-away key pair, do the exchange with the recipient's public key.
2. Turn the shared secret into two keys ([HKDF](sha-hmac-hkdf.md)): one for AES, one for HMAC.
3. Cipher the message with AES (CTR mode: any length, no padding).
4. Add an HMAC **tag** so any change is detected.
5. Output: throw-away public key, nonce, ciphertext, tag.

The recipient redoes the exchange with their private key, **checks the tag first**, then
deciphers. Wrong key or modified byte: exit 84.

## How it works in my_pgp

```
$ ./my_pgp X25519 -g                  # prints a private seed and its public key
$ echo hello | ./my_pgp X25519 -c <public> | ./my_pgp X25519 -d <seed>
hello
```

Keys are in the **Ed25519** format (the signature version of the same curve, as in the
subject's example); my_pgp converts them to X25519 internally.

## Is it secure?

Yes: X25519 is what TLS 1.3, SSH and Signal use. Our hybrid mode adds authentication (the
tag), so unlike the RSA and PGP modes, tampering is detected.
