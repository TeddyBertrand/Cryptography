# Crate `x25519`

[← Guide index](../README.md#crate-reference) · Source: [crates/x25519/src](../../../crates/x25519/src) · Depends on: [aes](aes.md), [core](core.md), [encoding](encoding.md), [hash](hash.md), [random](random.md) · Theory and optimisations: [X25519 and Ed25519](../techniques/x25519.md)

## Goal

The second asymmetric system (bonus): X25519 key agreement (RFC 7748), Ed25519 keys (RFC 8032)
as in the subject's example, and hybrid encryption built on them (ephemeral X25519 +
HKDF-SHA256 + AES-256-CTR + HMAC-SHA256).

## Public API

| Item | Description |
|---|---|
| `generate_key_pair() -> ([u8; 32], [u8; 32])` | `(public, seed)` in Ed25519 form: `X25519 -g` |
| `cipher(plaintext, public_hex) -> Vec<u8>` | `ephemeral_public ‖ nonce ‖ ciphertext ‖ tag` |
| `decipher(ciphertext, seed_hex) -> Vec<u8>` | Checks the tag, then deciphers |
| `check_key(hex)` | Validates a 32-byte hex key before stdin is read |
| `x25519(scalar, u) -> [u8; 32]` | Raw RFC 7748 function (clamps the scalar) |
| `public_key(scalar)` | `x25519(scalar, 9)`: raw X25519 public key (ephemeral keys, timing harness) |
| `ed25519::scalar(seed)`, `ed25519::public_key(seed)`, `ed25519::to_montgomery(public)` | Ed25519 ↔ X25519 conversions |
| `FieldElement` | GF(2^255 − 19) arithmetic |

```rust
let (public, seed) = x25519::generate_key_pair()?;
let ct = x25519::cipher(b"Winter is coming", &encoding::hex::encode(&public))?;
let pt = x25519::decipher(&ct, &encoding::hex::encode(&seed))?;
assert_eq!(pt, b"Winter is coming");
```

## Design choices

- **Ed25519 keys** to match the subject's example pair; raw RFC 7748 keys are not accepted on
  the command line, but `x25519`/`public_key` stay raw for the protocol internals.
- **Encrypt-then-MAC**, tag checked in constant time before any decryption.
- **CTR mode** instead of ECB: no padding, so binary data and trailing zeros round-trip.
- All-zero shared secrets (low-order public keys) are rejected.
